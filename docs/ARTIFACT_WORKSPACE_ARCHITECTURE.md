# Artifact Workspace Architecture

The Artifact Workspace is a local-first, governed editing surface inside ImperaOS. Python owns the canonical domain, validation, workspace isolation, revisions, policy, audit, and export authorization. A persistent stdio RPC sidecar is the only domain bridge; it opens no network listener. Tauri exposes a narrow command allowlist and performs native file dialogs and atomic writes only after backend authorization. React owns presentation, bounded draft state, lazy editor loading, and conflict UX, but never becomes the policy authority.

Every artifact has one workspace, kind, schema version, data class, status, and immutable revision chain. Mutations carry an expected revision and idempotency key. The service validates content before the store writes a new content-addressed revision. A conflict returns a bounded envelope and offers refresh, compare, reload, or governed fork. Autosave coalesces drafts and never silently overwrites a newer revision.

Editors for document, form, code, flow, spreadsheet, canvas, and slides share the same descriptor, revision, selection, mutation, history, and export contracts. Kind packages are lazy chunks. Monaco and other workers are bundled locally; CSP permits no `unsafe-eval` and editors may not contact providers or arbitrary networks. Code execution, extensions, terminals, remote imports, and renderer-selected paths are outside the boundary.

Feature rollout is fail-closed. `artifact_workspace.enabled` is the global authority, followed by per-kind and export gates. Named backend profiles are `artifact_workspace_off`, `artifact_workspace_core`, and `artifact_workspace_full`; explicit environment flags may narrow them. Spreadsheet and canvas resolve to a verified commercial adapter or a bundled local fallback, and the backend capability snapshot reports the effective adapter without exposing entitlement material. Renderer environment values can only disable. Enterprise defaults are off. The legacy assistant projection remains available during rollback, while stored artifact data is preserved for read-only integrity checks and forward repair.

Operational health combines reconciliation, store integrity, bounded metrics, and redacted logs. Release evidence is produced by `scripts/run_artifact_workspace_release_gate.py` for one immutable candidate commit. Architecture decisions are recorded in `docs/adr/`; tool governance is specified in `docs/AI_ASSISTANT_ARTIFACT_TOOL_CONTRACT.md`.
